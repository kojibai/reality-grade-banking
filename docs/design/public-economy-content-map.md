# Public economy, learning and standards: complete page map

## Intended outcome

Build a public site that makes money, assets and markets immediately familiar, while giving an independent technical reviewer enough definitions, methods, original evidence and executable checks to evaluate the supported implementation. Preserve Bankeiz's existing visual language, one-account framing, mobile width and document-free page transitions. Reuse Receiz; add no duplicate financial or proof authority.

This is the proposed content and interaction design. It is not a published economic standard, a new conformance verdict, a released capability or implementation evidence.

## Information architecture

Five primary groups: **Banking, Assets, Markets, History, Standards**. The existing Learn index becomes the readable directory across all five. The proof-native economy and Global Market Cap are major destinations. Existing routes retain canonical continuity; unrelated synonyms do not become separate pages.

Every subject begins with a familiar name and answers a distinct question. The method and evidence establish the precision. Avoid unsupported claims of universal superiority, guaranteed adoption, investment return or certification. Do not describe a displayed valuation as executable cash, realized proceeds, a completed trade, deposit backing, liquidity or GDP.

## Conformance framing

Publish the standard's actual requirements, normative source, versions, capability scope, trust assumptions and reproducible tests. A verdict is bound to a specific implementation and assessed capability, not an institution's reputation or willingness to adopt.

- **Conforming:** the complete applicable requirements and required evidence have passed for the stated profile.
- **Nonconforming:** an observed, reproducible failure of an applicable requirement.
- **Not assessed / not demonstrated:** required assessment or evidence is absent. This is not a fabricated failure or a pass.
- **Out of scope:** the capability is outside that assessment's declared scope. It is not a synonym for refusing adoption.

The standard applies the same evidence rule to Bankeiz itself. Current release and device qualification boundaries stay visible in technical depth. A protocol-pinned conformance report is not production authority, current spend authority or universal certification.

Provide full failure and adversarial cases: altered sources, forged handles, changed recipient/amount/split, stale predecessor, replay, rollback, concurrent claims, interrupted execution, lost responses, incomplete lineage and unknown namespaces. Reuse actual existing checks and source artifacts. Publish a complete supported result, including failures and exclusions.

## Page design

Build on the current light institutional palette, typography, image treatment, spacing and restrained motion. Existing Learn and valuation pages are the reference. No new brand, no new login landing links, no unrelated application redesign.

Every substantial page has:

1. A direct answer and one clear purpose in its first viewport.
2. Original, topic-relevant imagery sized for its slot, with matching sharing artwork.
3. A useful demonstration, source exploration or visual interaction where it clarifies the subject. Educational examples are labeled and cannot authorize financial actions.
4. A plain-language explanation of what the reader can do and what the result establishes.
5. Optional depth for method, exact units, trust assumptions, limitations, source, tests and independent verification.
6. A relevant next action and two or three genuinely related pages, not the entire directory repeated below every article.

For technical names, express the purpose first. Use **Kai-Klok KKSv1** and the actual **☤KAI** glyph; never spell the symbol name as a visible product label. Preserve the approved Reserve Note, Settlement Note and Settlement Reserve Note titles and captions.

## Instant navigation and performance

Preserve the existing prerendered public-page catalog and in-document transitions. New destinations must open without a full document navigation, empty shell, replacement login, “opening” state or a redundant data request. Browser Back/Forward, deep links, canonical URLs, scroll restoration, page title, metadata and focus must continue to work.

Keep content available before an interactive enhancement starts. Reuse current held public data and deduplicated readers. Do not poll for guide content, fetch private account data on public pages, or recalculate a competing market model. Load large images lazily below the fold and keep heavy calculators/verifiers out of the account's initial import graph. Avoid blanket autoplay and honor reduced motion.

## Search and content quality

Each canonical page has a distinct reader need, useful original material, descriptive title/description, semantic headings, crawlable links, breadcrumbs, matching Open Graph/Twitter/iMessage image, an appropriate schema and a sitemap entry. Private or selected-receipt pages remain nonindexable. Do not create invented publication dates, unsupported structured-data claims or repetitive pages solely to target synonym searches. Keep current canonical URLs or use deliberate redirects.

Illustrative numbers must not be presented as current market evidence. A source-complete proof of a claim does not independently establish that claim's external truth, cash liquidity, rights transfer, regulatory recognition or guaranteed return.

## Acceptance evidence

- All published internal links resolve to a real complete page or explicitly external canonical source.
- No duplicated app financial authority, added private public-page request or extra data polling.
- Navigation between representative guide, economy, market-cap, category, reference and account destinations preserves the same document and behaves correctly under Back/Forward.
- Mobile widths 320, 390 and 430px plus desktop 1280px have no horizontal overflow or inaccessible content.
- Current and historical data use the existing admitted methods; no invented values, unsupported default zero or silently smoothed historical series.
- Exact publication and Note qualification boundaries are preserved in technical material.
- Existing tests and production build pass; affected visual and interaction evidence is captured separately from live financial qualification.
