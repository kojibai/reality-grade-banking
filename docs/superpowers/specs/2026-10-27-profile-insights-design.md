# Profile insights

The approved direction is a quiet chart icon, public Insights for visitors and
a deeper private dashboard for the open account's owner. Keep the Bankeiz
profile, booking, market rules and first paint unchanged.

Use the public counters already carried by the profile immediately. Do not turn
aggregate counts into an invented historical curve. The native owner dashboard
has real time buckets, per-original results, traffic and commerce figures; these
are not currently included in the public profile or portable account read.
Read that protected dataset only on the owner's explicit panel opening, through
the existing same-account app-state permission. Retain and coalesce the result
inside the open identity; reopening and selecting periods require no request.
Never put private analytics in a public profile seed, shared cache or receipt.

Reuse the existing Sheet, ValueChart and restrained typography. Public counters
remain visible while the owner data is genuinely pending. The private dashboard
shows real timeline charts, audience, listening, commerce, source attribution,
originals and recent activity. Missing observations remain missing. Explicit
refresh is available; there is no polling, speculative fetch or minimum loader.
Dispose/hide private views on account change, including in-flight results.

Approaches: deriving a private history from public totals would invent data;
eager owner loading would penalize every profile open. An explicit retained
owner read preserves both source accuracy and the already-settled public view.
The user has directed execution of this already-discussed design on main.
