# Short receipts

The explicit Share action saves the complete, curated receipt once. Its SHA-256 identifies immutable display bytes; it is a delivery address, never payment authority or independent verification of the financial event. Existing signed originals and source references retain their authority.

A compact sharing panel opens immediately and prepares `/receipt/<sha256>/`. Copy and native Share use a ready link from their own tap. Download original and View in Ledger remain available. Opening a record, scrolling, changing categories and ordinary account startup never publish anything.

The saved receipt includes the complete already-held funding context and source cohorts. No shortening step removes evidence. A short URL opens the fixed capture; View in Ledger opens the current public record. Old query/fragment receipt links remain valid. Offline sharing retains the original download and carried link; no unavailable short link is presented as saved.

Delivery reuses the existing Receiz immutable shared-object transport in a separate display-only namespace. Publication accepts bounded JSON, binds exact bytes to the path digest, limits writes, and cannot update an existing object. Reads validate the digest. It introduces no identity, financial signature, balance, settlement writer or new storage service. Only explicitly selected, curated public receipt fields leave Bankeiz.

Bank's short route loads the saved record once server-side and injects escaped initial receipt data. Browser rendering uses that seed rather than fetching again. Known successful saves and receipt bytes are retained locally; simultaneous preparation coalesces. Funding source and Full funding history remain independent collapsed disclosures.

Acceptance: full long Note graph and onward-payment history survive saving/opening; URLs stay under 110 characters; publication is absent on ordinary Ledger/receipt opening; safe fields exclude private metadata; wrong hashes, excessive bodies, malformed JSON and replacement writes fail; first rendering has all stored evidence; native sharing retains tap activation; legacy links still work.
