# Local financial composition: current qualification

The local session composes the matching SDK Source admission, financial
executor and exact-original publisher in the existing native browser module.
It does not load another verifier, enroll a key or perform a network request
as part of local confirmation. Existing Identity and SDK record signatures,
accepted ancestry and durable original retention remain required.

Dynamic programmes carry the pricing operands. Buy and Sell calculate with
the existing Market formula at the action's original Kai; their historical
opening prices are consistency checks, not frozen execution prices. Wallet
and asset valuation continue locally. Earlier local trades affect later
prices and cost basis. Reconnect sends the exact causal sequence of original
bytes; it cannot obtain a new quote or execute an action again.

The synthetic integration uses actual preferred SDK cryptography, Source
admission, reducers, signatures and durable-commit mechanics. Its issuer,
accounts and transport are explicitly fixtures. It tests offline Send,
Buy/Sell at different pulses, retained growth, cold recovery, identity scope,
optional presentation failure, ordered reconnect and idempotent retries.
The native source reproduction also checks that financial arithmetic is
extracted from the included canonical sources and shares the existing
valuation core. No physical-device or real-money test is claimed.

## Activation boundary

This session composition is not yet selected by the application's existing
Send and Market buttons. Source preparation, incoming-credit succession and
custody handoff must be qualified and connected before activation. Ordinary
connected functions retain their existing path. Passing these component tests
does not establish a complete consumer offline flow.
