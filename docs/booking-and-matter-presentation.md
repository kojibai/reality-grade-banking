# Calendar, Digital Matter and contact presentation

The public `/book/` guide explains Calendar, personal booking, free/paid offers, per-guest appointment pricing, invitation/meeting continuity and optional Business Twin booking. Source-bound examples render the existing components at build time; local controls select inert examples. They create no appointments, messages, identities or payments. Visible walkthroughs loop; hidden, offscreen and reduced-motion states suspend automatic progression.

Personal booking remains at `/book/:username/`, with the same request, Twin, Calendar, payment and confirmation code. Only its internal HTML document moved to `booking/index.html` so `/book/` can be the public guide. Personal sharing metadata retains its existing owner-specific crawler route.

Help and contact actions open `/book/bjklock/` in a retained in-place dialog. The personal booking document owns its established behavior. No booking request or iframe starts before contact intent, and closing/reopening retains that document. Calendar data, email invitations and payment were not reimplemented. The page URL and underlying scroll position remain intact.

`/matter/` presents BJ Klock’s [Digital Matter definition](https://bjklock.com/p/digital-matter), attributed to the original essay, with an illustrated capture → seal → history → move → inspect sequence. Measurements, physical claims, ownership, custody and rights remain distinct and inspectable. The page links existing proof, conformance, asset and calendar experiences. The illustration does not issue proof or admit physical claims.

## Protected boundaries

- No account entry, PBI, identity storage, proof verifier, ownership, Settlement or Reserve logic changed.
- No new admission or signature authority was added.
- Shared CSS scoping is a side-effect-free helper. Importing it must never execute a preview build or create a recursive Vite server.
- Source inventory includes both the generated public guide directory and the actual personal booking HTML directory.
- Public guides receive dedicated canonical metadata, sharing images, sitemap entries and offline navigation assets. Personal booking remains a noindex template and is not advertised as the generic guide.
