# Live bank conversion — observed state

## Public Market: connected

The bank Market reads the same complete public showcase collection as
receiz.com/market. On 2026-10-13 the actual public-membership response reported
1,678 objects, `scope: whole-market-visible-showcase`, `source:
canonical-complete`, `isComplete: true`. The full public-snapshot response also
returned 1,678 live Market entries. This reports the feed's scope; it does not
assert discovery of private objects or independently verify every original.

The shipped public discovery cache is actual source data with its observation
date preserved, not invented sample assets. It is labeled as a public
projection and refreshed through the same public GET contracts while Market is
visible. Details show the actual owner returned by the public showcase, with a
public profile link; the owner is never guessed from the creator or object ID.
Public source links preserve the original public exposure; no private data is
published. The next 50 rows render automatically when the end comes within
600 pixels of the viewport. All objects remain searchable immediately.

The original file verification path uses SDK 129 on exact original bytes and
matches the expected enclosing artifact digest. Only an actually obtained
canonical result can show verification. Listing values, chart projections,
network counts, public presence, and UI checks never admit ownership or funds.
Public objects have `canTrade: false` until the bank has an admitted offer,
verified ownership, and qualified financial execution.

The GET proxy is installed in Vite dev and preview. A production deployment
must run equivalent Node middleware; static hosting alone cannot serve
`/api/bank/public-market/*`. No deployment has been performed. Refresh reads
allowlisted Receiz sources without user cookies or bearer tokens. The raw
discovery transport is stripped of full works, private/session fields and
unrelated prediction books before reaching the browser.

`npm run market:seed` obtains a fresh dated public projection from Receiz; it
does not execute a trade or change an account. Cached values may lag the next
quote read and do not constitute an executable price.

## Full live bank: not yet qualified

The existing Account, deposits, ownership actions, currency creation and exchange
remain the previous explicit demonstration implementation. The new public Market
does not upgrade their JSON state to admitted proof or connect public IDs to
their reducer. The request to remove all demo flows and provide native Create /
Import Receiz ID entrance, returning local-identity restore, and complete live
financial execution remains unfinished.

The user selected a dedicated new bank application. No registered public client
ID or bank domain was supplied; this project has no bank credential configuration.
The template application's credentials are deliberately not reused. The exact
registered Receiz-generated client ID must be preserved through device-held
scope consent and native qualification.

Physical deposits require an actual bank/custodian's verified receipt of the
asset. Platform liquidity requires actual eligible funded Reserve or Settlement
sources. Fractional sale/currency actions require genuine ownership/backing
sources and atomic payment/delivery recovery, not a sealed assertion of a new
balance. None of those operator-side facts have been observed for this bank.

All three local packages are pinned to 129.0.0. The currently connected MCP host
reported its marketplace release as 128.0.0 and no granted scopes. Its financial
execution restriction cannot be bypassed by swapping its profile or running a
financial SDK command through the agent. A future app's own device-authorized
native SDK runtime is a separate integration, whose real qualification and
commit/recovery/restore evidence must be recorded before claiming live funds.

skills: `8d0b5b839d02d9efbd4306cc99410595a183705c2670b76d2567eaaaade99065`.
This read is not execution or value authority. Financial ordering and expiry
must use admitted KKS/Kai coordinates; dates shown in public details are local
descriptive display only.
