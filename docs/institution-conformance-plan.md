# Public institution receiving kit — implementation contract

User request: this public repository should contain what developers and receiving institutions need to handle proof-backed notes and digital payments in conformance. The public language is value-native and conformance-based. Unknown conformance is never labeled a proven failure, and an unfinished Bank route is not attributed to an institution.

The kit will provide pinned v129 SDK/MCP/AI Skills and registry bindings; a normative receiving checklist; machine-readable capability/status and required evidence; executable artifact inspection and negative conformance vectors; the native Reserve Note receiving/redemption contract; SDK edge-payment integration references; exact recovery, custody, temporal proof and first-paint rules; and an explicit distinction between inspection, admission and committed receipt. Public examples contain no production identity, account opening, secret or executable financial instruction.

Read-only note verification will be a separate generated module compiled from the same native v129 source used by the Bank runtime, with canonical roots and provenance. It will not create a new authority profile, broaden the Bank's protected origin/client allowlist, or label an institution conformant from a self-reported result. No new dependencies or SDK versions are required. SDK runtime handles stay in-process; crossing a boundary requires exact-byte reverification.

Existing funding/redemption services remain specifically authorized to the Bank client/origins. Third-party production receiving requires its own identity, application consent, qualified custody and explicitly authorized native integration. A public repo cannot grant these permissions. Settlement Note funding and generic in-app digital transfer execution are not implemented by adding the kit and must remain visibly unqualified until native proof/admission and execution evidence exists.

Verification: unit/mutation tests, pinned artifact/registry checks, read-only CLI and browser import/inspection checks, unchanged canonical financial runtime, source-map/provenance audit, full Bank tests/typecheck/build, and independent review. Positive financial/hardware and independent receiver qualification evidence must be supplied by the institution before a live conformance claim. Documentation and checker output alone remain subordinate evidence.
