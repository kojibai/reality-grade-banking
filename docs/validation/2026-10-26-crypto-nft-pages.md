# Crypto and NFT page verification

Scope: `/crypto/`, `/nfts/`, alias `/nft/`. Implemented in the Bankeiz repository on main, preserving the existing page suites and native account/financial behavior. The public pages create no financial authority or token-custody mechanism.

## Binding and practical actions

The existing Receiz EVM source tools and OTC interface supply wallet-control attestations, native-asset balance and ERC-721 owner observations, portable proof creation and export. The optional tool link is `https://receiz.com/otc`. The pages explain the difference between a source snapshot and custody, current chain ownership, a token transfer, funded Reserve/Settlement, actual asset rights, application integration and qualified offline financial execution. The main CTA uses the existing fixed-owner BJ Twin and native conversation/contact/calendar paths, with each page's exact canonical Bankeiz context.

## Verification

- The page/context tests first failed because the new modules did not exist. The final focused suite passes nine tests, including a real shared composer with synthetic transport continuing through two natural replies and retaining the first accepted operation as the next reply reference. There is no cold Twin call.
- A share-image connector fill defect was found in the generated PNGs. A transparency contract failed before the correction and passed afterward; both final images were inspected without the black fill or clipped text.
- The complete Bankeiz suite passes 554 files and 3,500 tests. TypeScript passes.
- The production build passes, including public first paint, retained navigation, all 147 unique social cards, canonical metadata, sitemap, structured data, exact source archive, license notices and offline resource checks.
- The unchanged shared CSS plus JavaScript is 14,978 gzip bytes, below its 15,000-byte budget. New styles are page-only; artwork is carried SVG with no external asset request or new shared JavaScript.
- Browser inspection covered 320 px and 390 px mobile widths and 1022 px / 1280 px desktop widths. Both pages had zero horizontal overflow. Artwork remained within its figure; headings and conversation destinations were below the fixed header. Animated object transforms were observed running. The reduced-motion and hidden-document rules are covered by CSS contracts.
- Repeated Crypto CTA activation reached the same conversation after returning to the top. Retained navigation between Crypto and NFTs preserved page styling and canonical metadata. Direct `/nft/` served the full NFT document with canonical `/nfts/` metadata. Footer current-page omission and explicit `/u/` profile paths are covered by tests.
- One independent final review inspected all source/wiring, the rendered anchors and SVG paint references and both final share images. It found no Critical or Important defects; no deferred minors were reported. Browser execution remained the coordinator's responsibility and was checked as above.

## Boundary

Local browser/contract verification did not connect a real wallet, seal a customer's asset, invoke production AI, send a production message, create a contact or calendar appointment, transfer value, alter DNS, run migrations, push or deploy. Existing production financial writers, account entry and existing paid flows are unchanged. Deployment and any real customer asset/payment qualification remain separate.
