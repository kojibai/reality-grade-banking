## Reproducible verification

The final candidate is checked with the following commands. The committed
[engineering record](../../src/content/conformance-baseline.json) contains the
actual complete test outcomes, timestamps, individual cases and exact input
hashes. It is produced from fresh Vitest JSON after a before/after source
snapshot comparison. Its own generated output is excluded from its digest to
avoid self-reference.

```sh
npm run release:check
npm run typecheck
npm run receiver:check
npm run native:check
npm run native:rebuild -- --sdk
node scripts/conformance-reference.mjs
node scripts/conformance-contract.mjs --adapter node scripts/conformance-adapter.mjs
node scripts/conformance-certificate.mjs --check
node scripts/conformance-baseline.mjs --snapshot /tmp/bankeiz-v3-test-sources.json
npm test -- --maxWorkers=4 --reporter=default --reporter=json --outputFile=/tmp/bankeiz-v3-vitest.json
node scripts/conformance-baseline.mjs /tmp/bankeiz-v3-vitest.json --sources /tmp/bankeiz-v3-test-sources.json
npm run build
npm run source:verify -- --rebuild
```

The lockfile is also installed into an isolated temporary directory with
`npm ci --ignore-scripts --offline --no-audit --no-fund`; it does not replace
the working application's dependencies. The clean source-archive rebuild uses
the already installed, version-checked public npm tools. This is source and
dependency reproducibility evidence, not a new external security audit.

The build checks pinned packages, canonical Identity artwork, public titles and
social images, the published conformance original, TypeScript, native verifier
resources, public pages, offline inventory, licensing and exact source archive.
The independent archive check extracts the distribution and builds the application,
including reproduction of all 211 supplied SDK JavaScript outputs. Conformance
console code and styles remain outside the Bank entry's initial import graph.
Checkout retains its dedicated entry without Market, messaging or financial
requests on the read-only cold-shell check.

## Browser and capability evidence

Isolated local Chrome checks cover the twelve browser verification groups,
33-case contract run, reopening the actual public PNG, entrance evidence popover,
mobile resource links and public headers. Header layouts are inspected at 320,
390 and 1440 pixels. The built Releases page retains v1/v2, exposes v3 resources

The built checkout check confirms recipient/amount, readable no-JavaScript shell
and absence of Market/history/messaging/payment requests on its cold path.
Identity restoration is deliberately stubbed in isolated conformance/checkout
checks so inspection cannot enroll an account or submit a financial action.

and authorized operations. Keep those outcomes distinct from synthetic fixtures.

## Publication handoff

1. Push the reviewed release commit on main and inspect its completed CI/build.
2. Record the exact deployed revision, source inventory and applicable capability
   evidence. Preserve original identities and unresolved operation references.
3. Publish `v3.0.0` at that exact release commit, using the
   [full release notes](3.0.0.md). Preparation creates neither tag nor hosted release.
4. Retain the matching complete corresponding-source archive, inventory/digest,
   resource manifests, LICENSE, NOTICE and third-party notices. The build emits
   their exact identifiers; embedding an archive's own hash in its inputs would
   be self-referential. `/legal/` exposes source for the deployed build.
5. Append the actual publication date, tag/commit and release URL to the index
   after publication. Retain prior source and evidence through rollback.

See [release process](../release-process.md) and [source distribution](../../SOURCE.md).
