# Bankeiz 1.0.0 release readiness

**Status: candidate specification. Not an official released version.**

Bankeiz product version 1.0.0 is independent of Receiz protocol/package
version 129.0.0. The current application package remains 0.1.0 until the
release gates below are satisfied. No tag, publication or deployment is
established by this document.

## Intended Note capability

One create, receive, send and deposit experience. Qualified custody supports
continuous offline transfers without periodic server confirmation, within its
actual resources and trust policy. Other devices can hold and inspect a valid
incoming original offline and use connected exclusive consumption for their
next send. Missing incoming finality stays pending. Exact value, source and
history remain attached in both paths.

The [continuity standard](../note-continuity-standard.md) defines the full
contract, ownership boundary, integration responsibilities and required tests.
No unqualified device is silently treated as qualified.

## Release blockers

- Current, implemented Receiz connected Note custody profile and SDK/host
  capability. Legacy Connect mint/claim do not implement it.
- Independent complete-proof evidence for issue, offline receipt, exact-head
  consumption, next send and once-only deposit on an ordinary browser.
- Qualified local physical-device evidence, including real rollback and
  interrupted-operation recovery. Synthetic authenticators are insufficient.
- Cross-custody migration proving the prior spend authority is retired and no
  account/Note or connected/local duplicate membership exists.
- Retained-intent compatibility and actual deployed funding/writer/signer
  qualification described in [the existing release gates](../offline-notes-release.md).
- Final exact build, deployment, registry, source archive, license and full
  release-lock evidence. An MCP context or package version check alone cannot
  satisfy these financial gates.

## Publication sequence

1. Complete the missing Receiz capability and pin its actual compatible
   contract. Keep qualified local verification unchanged.
2. Integrate and exercise both paths with source verification at every
   consequential boundary. Preserve existing originals and pending records.
3. Record exact commands/results, synthetic versus real device scope,
   independent verification, current host/build hashes and exclusions.
4. Run [the release process](../release-process.md), including complete tests,
   receiver checks, mobile review, production build, source and licensing.
5. After the evidence is complete, update product package/lock metadata and
   release notes to 1.0.0, review the final immutable commit, then let the
   authorized operator publish that exact version.

Describe verifiable capabilities and their tested scope. Do not claim universal
device qualification, unlimited offline capacity, an available accessory,
government endorsement, or superiority over every other monetary system.

## Evidence ledger

Implementation audit and public standards are preparation. Financial
qualification is **not complete**. No new financial action, real-device
credential ceremony, public release or production migration has been performed
as part of writing this release specification.
