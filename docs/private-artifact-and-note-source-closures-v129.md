# Account source closures — v129

The v4 public account statement preserves the existing account-proof image,
verification page, review and explicit sharing controls. It uses the same v129
canonical Record/Seal and existing financial-root signature. No SDK, MCP or AI
Skills package version, financial signer or SQL schema changes.

## Private artifact originals

The account's accepted Showcase source selects the inner artifact head. The
complete existing owner archive supplies its originals, hidden membership,
ownership continuity, materials, attachments and reachable history. Every read
reopens the enclosing package and runs the existing complete owner admission.
An archive at another head, even for the same owner, cannot replace that head.

Authenticated `POST /api/connect/account-proof/sources?applicationId=…` accepts
only `{archiveBytesB64u}`. It requires the existing account-read scopes plus
`receiz:domains.write`. It retains the exact archive privately after admission
and returns its digest. It neither publishes the archive nor changes account
authorization, financial state or sharing consent. The browser excludes an
Identity Seal before transmission; the host independently verifies archive
privacy and full source closure. The same private operation crosses the closed
Crystal native port as `account.retain-source`, subject to protected custody.

The existing account-proof section contains a collapsed **Private source
files** control. Choose the original owner archive, then review the account
proof. Publication still requires its separate explicit consent. This bounded
Vercel route accepts decoded archives through 3 MiB and separately allows for
encoding/envelope overhead. Larger original archives must be retained through the trusted source
host's `retainBankNativeAccountArtifactSource` operation; they must never be
truncated or replaced by a list of display rows.

The private digest index locates bytes beneath the accepted inner head. It is
not an authority or current-head selector. Historical disclosure pins its exact
archive digest and does not consult the current index. Public statements carry
only that digest and the allowed projection, never archive bytes or capability.

Intrinsic proof value follows the shipped public-owned artifact projector at
the sealed source's Kai coordinate. Hidden originals are reopened for complete
custody but are not assigned public intrinsic value. Verified possession does
not become ownership. This intrinsic component never becomes a wallet credit.
Unselected private heads, imported/non-native artifact genesis and effective
Creation Sigil entitlement policy require their actual source admission; this
implementation does not infer those rights from a profile or manual row.

## Offline Note funding

The source closure reopens original native allocation, qualified funding,
cancellation, Note lineage, terminal consumption and accepted credit sources.
It reconciles all redemptions against each original funded pool, including a
terminal whose local credit coordinate differs from that original pool.
Duplicate consumption, missing bytes, altered records and excess redemption
refuse publication. An interrupted allocation remains funded until an accepted
cancellation returns it; absence of an attached Note is not zero funding.

**Outstanding Note funding** means account-origin value committed to Notes,
including Notes already sent to others. It is separate from spendable balances
and does not assert that the originator currently holds those Notes. Reserve
keeps its original dollar denomination; Settlement keeps exact Phi and uses
the statement's captured deterministic quote for its dollar display.

A recipient-only redemption advances the origin account's offline source head
without changing its already-debited wallet. Current publication and live
refresh recheck that head. Immutable snapshots reopen their historical source
prefix and keep their original balances and funding component.

## Publication and recovery

Current production, consent admission, accepted append and cold replay reopen
the same full source frontier. A changed authorization, lawful inventory,
artifact archive, wallet, native asset or Note funding head rejects stale
publication. Bounded evidence references the selected original graph heads;
verification still reopens every required source, rather than flattening an
unbounded history into a statement's evidence array. Existing v2/v3 snapshots
retain their exact original verification and replay rules.

## Exact remaining custody boundary

Current v129 browser APIs verify historical Note activation, consumption and
lineage. They do not export an independently fresh proof of the device's full
current held inventory. Saved-file lists and funding allocations cannot supply
that claim. A generic new WebAuthn read assertion is also unsuitable: it changes
the strict counter used by irreversible custody. A current-holder account
aggregate needs the existing qualified custody implementation to expose a
source-bound, non-consuming inventory closure and its accepted successor rules.
This release does not invent that proof or label origin funding as possession.
If this device already holds a verified local Note account successor, Bankeiz
refuses exporting or newly publishing an older remote account source as its
complete current proof. It checks again across awaited reads and publication.
Balances and Notes remain available, and existing public-sharing status and
the live-update off switch remain accessible.

The deployed Crystal installation must mount these reviewed runtime ports,
retain the exact private/public sources and qualify its protected writes.
Local cryptographic, restart and transport tests do not claim that an
undeployed service or physical authenticator is live.

Trusted configured startup selects v4. A host composing the native factory
directly must use `createBankNativeAccountProofRuntime({ directory,
applicationId, includeSourceClosures: true, ownerReceizIdForUser })` with its
existing admitted identity resolver. The factory's older explicit construction
continues to support the original v3 contract; request bodies cannot select or
install a runtime. Keep both old snapshot readers enabled during an upgrade.
