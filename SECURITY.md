# Security reporting and operating boundaries

Do not publish private identity material, source proofs, keys, custody state, tokens, payment details or exploit payloads in an issue. For a suspected vulnerability, contact a repository maintainer privately through an available verified contact on the repository owner's GitHub profile. If this repository enables GitHub private vulnerability reporting, use **Security → Report a vulnerability**. No unverified email address, guaranteed response time or bounty is specified here.

Include the affected commit, capability/rail, minimal redacted reproduction, expected invariant, observed impact and any safe source digests. Keep private originals in protected custody for a maintainer-agreed channel. Never move real funds, access another person's private account or weaken production trust to demonstrate a report.

Protect the device-held Identity Seal and native hardware custody; keep private APIs no-store. Treat public market/profile data, QR/NFC requests, images, source maps, reports and model output as untrusted inputs. Only the canonical exact-source admission and qualified execution lifecycle authorize changes. See the [receiving standard](institution/receiving-standard.md).

Production operators own application registration, identity consent, approved native integrations, operational key custody, service availability, monitoring and incident response. A clone of this reference does not acquire the Bank's hosted service access or establish regulatory authorization.
